# ActionDoc AI — 현재 개발본 0.3.0

PDF·HWP·HTML·TXT·MD와 붙여넣은 안내문을 읽고, 조건·기간·조치·원문 근거를 확인하는 Mac 앱입니다. 이 폴더가 최종 프로젝트입니다. 실행은 바로 아래 **ActionDoc AI.app**을 더블클릭하고, 소스 수정은 **desktop/Sources**와 **src/main/java**에서 진행합니다.

문서는 파일당 최대 **50MB**까지 입력할 수 있습니다. 파일 용량과 별개로 추출 본문은 160,000자, PDF는 50페이지까지 처리합니다.

## PDF 처리 속도와 진행 표시

PDF 렌더링과 텍스트 추출은 한 스레드에서 수행하며, 렌더링이 끝난 페이지 이미지만 최대 두 쪽씩 OCR 처리합니다. OCR용으로 대기 중인 렌더링 이미지는 두 쪽으로 제한합니다. 인식 해상도와 한국어·영어 정확도 설정은 동일하며, 결과는 원본 쪽 순서로 합칩니다. 한 쪽이라도 실패하면 진행 중인 OCR을 취소하고 불완전한 문서는 반환하지 않습니다.

Mac 앱과 웹 화면에 `PDF 18 / 92쪽 읽음`처럼 실제 완료 쪽수를 표시합니다. 진행 정보는 업로드한 세션에서만 조회할 수 있고 문서 본문은 포함하지 않습니다.

2026-11-07 로컬 측정(각 1회): `AX실증밸리조성사업 사업설명회_책자(최종본).pdf` 24.7MB·92쪽, OCR 85쪽의 문서 읽기가 **95.654초 → 65.266초(약 32% 단축)**였습니다. 추출 본문 131,750자, 원문 블록·쪽 번호·마크다운·경고가 모두 같았습니다. AI 요약 호출은 측정에 포함하지 않았습니다. 문서 구성과 Mac 상태에 따라 시간은 달라집니다.

성능 재현은 Maven 테스트에 `-Dtest=PdfPerformanceTests -Dactiondoc.pdfBenchmark=/문서/경로.pdf`를 지정합니다. 선택적으로 `-Dactiondoc.pdfBenchmarkOutput=/임시/결과.json`에 추출 결과를 저장할 수 있습니다. 이 테스트는 실제 Mac OCR을 사용하며 외부 AI를 호출하지 않습니다.

## HWP 문서 입력

한글 HWP 5 형식의 `.hwp` 파일을 선택하거나 앱에 끌어다 놓으면 본문과 표·글상자 안의 글자를 읽어 기존 분석·원문 인용·후속 경로·작업 등록 흐름으로 연결합니다. 파일은 50MB, 추출 본문은 160,000자까지 지원합니다. 별도 한글 프로그램 설치나 외부 변환 서비스 전송은 필요하지 않습니다. AI 분석을 선택하면 기존 전송 동의 절차를 적용합니다.

- 원본 쪽 번호와 표의 시각적 배치는 보존하지 않습니다. 근거는 `본문 · b번호`로 표시합니다. 내부 API의 `pages`와 `page`는 쪽 번호를 알 수 없다는 의미로 `0`입니다.
- 이미지 속 글자와 화면에 주소가 쓰여 있지 않은 하이퍼링크 대상은 추출하지 않습니다. 이미지 문서는 PDF로 저장해 입력하면 기존 OCR을 사용할 수 있습니다.
- 암호·DRM·배포용 보호 문서, 구형 HWP 3, HWPX는 이번 지원 범위에 포함되지 않습니다. 보호되지 않은 HWP 5 또는 PDF로 저장해 입력하세요.
- 압축 해제 크기는 128MB로 제한합니다. 라이브러리에서 잘릴 수 있는 매우 긴 문단은 오류로 안내하므로 한 문단을 65,000자 이하로 나누거나 PDF로 저장하세요.

HWP 파서는 Apache 2.0 라이선스의 [hwplib 1.1.11](https://github.com/neolord0/hwplib)을 사용합니다.

## 후속 조치 바로가기

분석 결과의 **바로 이어서 할 수 있는 일**에서 문서에 실제로 적힌 웹 주소·문의 전화·이메일로 이동합니다. AI 출력의 주소를 실행하지 않으며 원문 블록, 주소, 인용 근거의 대응을 서버와 앱에서 확인합니다.

- 웹 주소: 브라우저로 열기, 주소 복사, 원문 근거 확인
- 사이트 안의 메뉴 경로: 원문에 명시된 경우만 표시
- 이메일: 수신 주소만 채워 메일 앱 열기. 문서·개인정보·제목·본문을 자동 첨부하지 않음
- 전화: 전화 앱 열기와 실제 연결 번호 복사. 번호 범위는 첫 번째 번호임을 표시
- PDF의 URI 링크 주석도 읽으므로 표시 글자에 주소가 없어도 연결 가능
- 문서에 세부 페이지가 없으면 신청 페이지 주소를 만들지 않음
- 접수 기간이 지난 경우 공고·후속 안내 확인으로 표시. 과거 기록도 날짜를 다시 비교
- 이전 버전 기록에 바로가기가 없으면 원본을 다시 분석해야 함

신청서 자동 작성·제출, 자동 이메일 발송, 자동 전화 기능은 포함하지 않습니다. 실제 목적지의 최신 신청 가능 여부를 서버에서 조회하는 기능도 없습니다. 공문에 적힌 주소로 이동하는 기능이며, 링크 대상 사이트의 소유자나 안전성을 보증하지 않습니다.

## 현재 분석과 배포 상태

회원가입 없이 사용하고 기록·작업은 사용자 Mac의 `~/Library/Application Support/ActionDoc AI/records.json`에 저장합니다. OCR은 앱에 포함된 Apple Vision 도구로 실행합니다. 항목 정리와 후속 경로 추출은 AI 키 없이 사용할 수 있습니다.

사용자 화면은 `무료 기본 정리` / `내 API 키로 상세 요약`을 선택한 뒤 `문서 요약하기`를 누릅니다. 기본값은 무료이며 API 키를 저장해도 자동으로 AI 모드로 전환하지 않습니다. 무료 모드는 로컬 원문 발췌로 API 비용이 없고, AI 모드는 문서 전송·사용 비용 동의 후 개인 API 키로 사실 추출 → 요약 → 검증을 수행합니다. 선택한 요약 목적도 AI 종합 단계에 전달합니다. Mac에서 개인 키를 키체인에 등록할 수 있으며 웹은 서버에 설정된 키를 사용합니다.

ChatGPT 계정 연동은 아직 구현하지 않았습니다. 2026-11-08 기준 공식 Sign in with ChatGPT는 공개 소스 앱 및 승인된 비공개 앱 등에서 구독 사용량 연동을 지원하므로, 프로젝트의 배포 형태·연동 자격 확인과 OAuth 등록이 필요합니다. API 키 방식은 ChatGPT 구독 사용량을 자동 사용하지 않습니다. 공식 안내: https://developers.openai.com/siwc/quickstart


실제 AI 분석은 현재 개인 API 키 설정을 이용하는 구현입니다. OpenAI 경로는 문서의 조건 추출 → 요약·사용자 상황 비교 → 근거 검증을 수행합니다. 개인 키가 필요 없는 익명 공개 서비스와 무료 운영 환경은 아직 연결하지 않았습니다. 해당 배포 방식을 확정하기 전까지 개인 앱 구현과 공개 서비스 목표를 구분합니다. 키는 키체인에 보관하고 소스·앱에 넣지 않습니다.

## 코드

- `src/main/java/ai/actiondoc/ActionRoutes.java`: 원문 경로 추출과 검증
- `AnalysisService.java`: 분석 뒤 원문 경로 첨부
- `DocumentService.java`: 본문/OCR 및 PDF URI 주석 추출
- `PdfPagePipeline.java`: 제한된 OCR 동시 처리와 쪽 순서·진행 정보 유지
- `HwpTextExtractor.java`: HWP 형식·보호 여부·압축 크기 검사 및 본문 추출
- `desktop/Sources/ActionRoutesView.swift`: 바로가기 UI
- `desktop/Sources/Models.swift`: 열기 직전 주소·원문 검증과 만료일 확인
- `AppModel.swift`: 사용자 클릭에 따른 외부 앱 열기·복사
- `Storage.swift`: 기록·작업 저장과 이전 데이터 호환

## 실행과 검증

Apple Silicon Mac, macOS 14 이상용입니다. 배포 앱은 Java 런타임을 포함합니다. 소스에서 빌드할 때는 앱을 종료하고 `./desktop/build.command`를 실행합니다. Xcode Command Line Tools, Java 17 JDK, Maven이 필요합니다.

2026-11-07: Java 테스트 44개 통과, Mac 자체 검증 통과. 실제 서울시 5페이지 공문에서 웹사이트 1개와 전화 2개를 표시하고 브라우저에서 청년몽땅정보통이 열림을 확인했습니다. 전화·메일의 실제 통화/발송은 실행하지 않았습니다. 실제 유료 AI 호출은 키가 없어 미검증입니다. 공개 CI로 옮길 때는 기존 공문 회귀 테스트의 개인 파일 경로와 빌드 도구 경로를 정리해야 합니다.

2026-11-07 HWP 추가 검증: 전체 회귀 테스트와 변경 후 HWP/API 테스트를 합쳐 Java 53개 통과(실제 HWP 공문 검증 포함), Mac 빌드·자체 검증 통과. 압축/비압축, 여러 구역, 표·글상자, 수동 줄바꿈, 원문 근거·주소 추출·작업 등록, 보호/손상 문서 및 크기 제한을 확인했습니다. 실제 HWP 검증 파일은 저장소에 넣지 않았으며 `-Dactiondoc.hwpFixture=/문서/경로.hwp`로 선택해 검증할 수 있습니다. HWP를 이용한 유료 AI 호출은 실행하지 않았습니다.

2026-11-07 용량 확대: 파일당 10MB에서 50MB로 확대했습니다. Mac 선택·전송, 웹 검사·표시, 서버 업로드·오류·설정 API를 함께 변경했습니다. HWP 압축 해제 한도는 32MB에서 128MB로 확대했습니다. 11MB HWP의 본문 추출, 50MB 경계값과 한도 초과 거부, HTTP 업로드 설정 일치를 검증했습니다.

### 시연 범위와 배포 전 작업

- PDF는 50쪽까지 허용하며 51쪽 이상은 OCR 전에 거절합니다. 필요한 부분을 별도 PDF로 저장해 사용합니다. 파일 50MB, 추출 본문 160,000자 제한도 유지합니다. HWP·HTML·TXT·MD는 원본 쪽수 측정이 불가능하므로 쪽수 제한을 적용하지 않습니다.
- 요약 목적은 전체 정리 / 공문·업무 요청 / 지원사업·모집 공고 / 요금·계약 안내입니다. 선택 목적에 맞는 항목으로 원문을 발췌하며, 제한·예외도 별도 표시합니다. 원문 일치가 의미 이해나 자격 판정을 보장하지 않습니다.
- API `/api/analyses`의 선택 필드 `purpose`는 GENERAL / BUSINESS / SUPPORT / CONTRACT입니다. 생략하면 기존 전체 정리와 호환됩니다.
- 배포 직전 작업: 운영자 제공 AI 연결, 문맥 기반 요약 품질 평가, 사용자별 사용량·비용 제어. 무료 모드는 로컬 발췌를 유지하고, 개인 API 키의 상세 요약은 사용자가 선택한 경우에만 호출합니다. Mac Vision OCR은 글자 인식 기능이며 LLM 요약이 아닙니다.
- 이전 92쪽 PDF 성능 측정은 100쪽 허용 당시의 기록입니다. 현재 50쪽 제한에서는 해당 파일 전체를 넣을 수 없습니다.
